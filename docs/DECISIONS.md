## Fixes to Muse's AirGrid pack (Oct 29)
- **L7 · Battery arithmetic.** Muse's golden timeline broke its own rates (D-02 docks ~36% not ~42%; D-07 at 17:22 would be 21%, below reserve; D-05 relay and D-08 numbers inconsistent). Replaced by the computed timeline. Every number now comes from the checker.
- **L8 · No auto pool.** Muse let a 5th drone fall into an "auto pool", which made `PILOT_SATURATED` meaningless. Now: every airborne drone has a named pilot (kazum, DP-1, DP-2), max 4 each, max 12 airborne.
- **L9 · Latency belongs to code.** Auto-launch, rotation, backfill, slot booking ("confirm slot, then RTB"), track relay and safety RTB are sim policies. Agents narrate, propose, handle exceptions and talk to humans. An LLM is never in the critical path of a launch.
- **L10 · Demo clock.** Muse's 1 real s = 1 sim-min is too fast for LLM agents. Now 0.5 sim-min/s with holds on pending approvals and agent-owned beats (max 45 s), ⏩ skip otherwise, every skip marked in the video.
- **L11 · Agents can't read the repo.** Runtime agents run from `~/airgrid-agents/<name>/` with only their instruction file and `.env`. API never serves future events or the suspect's future path.
- **L12 · Ready floor.** ≥ 3 READY drones spread across sectors at all times (golden minimum is 4 at 17:56). Patrol backfill when a patrol drone is diverted (D-07 at 17:41).
- **L13 · Rooms fixed at 8 + #test-room.** Muse's counts varied (6 + dynamic, 7, 8). `#incident-1` and `#incident-2` are pre-created and reused.
- **L14 · Decisions mechanism.** Unknown until the `#test-room` probe. Order of preference: World Bot writes the entry as a custom client → an agent writes it → kazum creates it from the World Bot's one-line summary. Probe result (Oct 30, `#test-room`, see L40).
- **L15 · Dashboard.** Static HTML/JS + SVG + SSE served by FastAPI, not Streamlit (1 s animated map with interpolation). Started Oct 31 in a parallel lane from a recorded replay, not built last.
- **L16 · Pre-week used.** Sim, rules, CLI, World Bot and dashboard before Nov 4. Hackathon days = agents, Switch, video.
- **L17 · No Faker.** Fixed name lists and templates.
- **L18 · Unverified stats removed** (Futian 65 docks, ~6,000 US programmes, retiming ~50 m). Verified list in 00-PROBLEM. No real-world number is presented as our result.
- **L19 · Recording is derived state**, not a flag agents set: on only inside an open incident geofence, never in NR-HOSPITAL; every transition logged. `request_face_id` exists only to be rejected and logged.
- **L20 · Cut order** (01-PRD): Codex → unscripted segment → footage release → retiming/advisories → Tasks panel → dashboard polish → merge `#incident-2`. Never cut: auto-launch eyes-on, track approval, 0-gap handoff, PRIVACY_POLICY, NO_FLY_ZONE hold, PILOT_SATURATED, MISSION_EXPIRED, Decisions, scorecard.

## Design choices made while computing the timeline
- **L21 · Fleet size.** 14 drones, 12 pole docks (1 slot) + 2 hubs (3 slots) = 18 slots. Nearest dock ≤ 1.25 km anywhere, so ~2 min eyes-on is realistic. Thermal D-06, D-12 kept back for night/track (+0.75 km selection penalty).
- **L22 · P1 sits inside VIP-TEMP on purpose.** Activating the VIP zone takes P1 out of use (D-01 can't launch or land), a live trigger beat.
- **L23 · Chase choices.** D-13 is diverted while airborne at 60% (eyes on a moving target now beats a full battery 90 s later); relay by sprint from P12. Perimeter = D-14 (HUB-A), corridors = D-04 north, D-08 south, so kazum hits 4/4 and D-03 at 18:04 trips PILOT_SATURATED honestly.
- **L24 · Baseline** is patrol cars + one van drone team at J7 (setup 3 min, 40-min flight, 27-min charge, 5 min to pack up). Coverage ~9% is approximate (one of three loops, minus call-outs, swaps, weather) and labelled so. Ground-unit ETAs are `[sim]` until Phase 04.
- **L25 · Ports/IDs.** API `localhost:8740`. Approval ids `A-0001…`. Incident ids `INC-n`.
